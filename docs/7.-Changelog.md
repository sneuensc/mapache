# Changelog

Summary of what changed in mapache since the last release, for users upgrading from an earlier version.

## New Features
- **`vg giraffe` graph-based mapper** (`mapping.mapper: vg_giraffe` / `vg_giraffe_gam`) — new params `giraffe_params`, `keep_gam`, `software.vg`. Requires externally generated graph index files (not built automatically).
- **Two-phase "map → inspect → finish" workflow** — new `stats_after_rmDup` config section and `mapping_library` checkpoint rule (renamed from `mapping_libraries`): pause after duplicate removal, inspect per-library stats, adjust downstream parameters, then finish.
- **`SM_FINAL` sample-file column** — reassign libraries to a different final sample at merge time (merge or split individuals independently of the `SM` used for mapping/dedup); rewrites BAM `SM`/`RG` tags via `samtools reheader`.
- **`remove_duplicates.save_duplicates` option** and new `markduplicates_keep_duplicates` rule — optionally keep removed duplicates in a separate BAM.
- **`stats.preseq`** — library-complexity estimation (preseq `lc_extrap`), producing `.preseq.tsv`/`.svg` per library.
- **Per-level statistics control** — `stats.qualimap.level`, `stats.damage.level`, and a new `stats.mapping_stats` key choose which of `FASTQ`/`LB_rmDup`/`LB`/`SM` levels get reports/summaries; new `LB_rmDup_stats.csv` level.
- **New `depth` rule** (via `pysam`) for coverage statistics.
- **Second MultiQC report** at the post-dedup library level (`multiqc_mapache_library_rmDup.html`).
- **GLIMPSE2 support** alongside GLIMPSE1 for imputation.
- **Snakemake 8 support** — new default execution profile (`workflow/profiles/default/config.yaml`, using `snakemake-executor-plugin-slurm`), replacing the old `slurm/` cookiecutter profile (removed).

## Changed
- `stats:` config reorganized into nested `{run, mem, level}` blocks; `damage:` moved from top-level into `stats.damage`.
- `bamdamage` script rewritten: new `--length_min`/`--length_max` range flags, new `--ignore_N` flag, renamed output flags (`--out_damage`/`--out_length`).
- Report format switched from `.html` to `.zip`.
- Output tree gained `02_library/02_bam_after_rmDup/` and per-level `04_stats/03_summary/{level}/` folders.
- Dependencies bumped across the board: Snakemake 7.18.2 → 8.25.4, samtools 1.14 → 1.21, Picard 2.25.5 → 3.3.0, R 4.0.5 → 4.4 (plot scripts moved from `reshape2`/`data.table` to `tidyverse`), plus bwa/Bowtie2/FastQC/mapDamage/bedtools/seqtk/DeDup/QualiMap/MultiQC/bcftools bumps.
- `download.tries` is now configurable (was hardcoded to 3); md5 warnings/errors are now also written to the rule's log file.

## Fixed
- Verbose-log touch file moved under `.snakemake/`; the full verbose log is now also persisted to `{result_dir}/RUN_INFO.txt`.
- Fixed `get_md5_of_ID()` in `common.smk` (could call `test_md5()` on the wrong/missing value).
- Fixed a `vg_giraffe` mapper index bug; standardized error exits; hardened remote downloads.
- Added a missing conda environment for `samtools_filter`.
- Typo fix: "pricards" → "picards" in rule docstrings.
